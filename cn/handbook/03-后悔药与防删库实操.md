# 第 3 课 · 后悔药与防删库实操（让错误变得不疼）

> 概率模型永远不可能做到 100% 不犯错。真正的安全不是祈祷“AI 每次都完美”，而是**把犯错代价压到接近零——随时 3 秒退回，高危手滑进不来门**。

---

## 一、 零基础后悔药：Git 存档与分支

- 新手可以直接复制使用这份跨平台（零 `&&`）命令表：[`../guardrails/git-safety-cheatsheet.md`](../guardrails/git-safety-cheatsheet.md)
- 核心就三件事：
  1. 大改前跑 `git add -A` + `git commit -m "checkpoint"` 存个档；
  2. 还没提交就改乱了，用 `git stash push -u -m "broken"` 收进抽屉复原（后续想翻回用 `git stash apply` / `pop`，**禁用 `git reset --hard`**）；
  3. 已经提交进去才发现有 Bug，用 `git revert HEAD --no-edit` 安全生成一条撤销提交。

---

## 二、 防手滑减速带（Hook）+ `_trash_box/` 待清空回收盒

- **终端防手滑减速带**：不要指望在 Markdown 里写“禁止 `rm -rf *`”就能拦住上下文压缩后的模型。如果使用 **Claude Code**，可按 [`../guardrails/hooks/README.md`](../guardrails/hooks/README.md) 装上 `PreToolUse` 钩子，把常见通配符删除（如 `rm -rf *.py`）与 `git reset --hard` 用 `exit 2` 拦在门外。
  - ⚠️ **定位边界**：正则钩子只是第一道**防手滑减速带**（拦不住 `rm -rf src`、`python -c` 删文件等等价绕过），**真正的安全底座永远是 Git 存档 + 宿主终端审批开关**。
- **可逆清理（不永久积灰）**：平时清理废弃文件/旧脚本，先挪进已加入 `.gitignore` 的 **`_trash_box/`** 目录；等新版本跑稳一两天确认无遗漏引用，你随时可以痛快删空这个文件夹。

---

## 三、 万一真没开 Git 就把文件改坏了怎么办？

记住一条铁律：**文件一旦已经被 AI 截断、删半截或写花，严禁让 AI 继续在那个损坏文件上按行号做修补！**（在坏尺子上算偏移只会切掉另一半。）

立刻先将损坏文件改名留证为 `.broken`，按下面 **3 步日常优先顺序**抢救：
1. **IDE 自带本地历史（最快、零配置、拯救 90% 的无 Git 事故）**：
   - **VS Code / Cursor**：左侧资源管理器最下方展开 **Timeline（时间线）**，选中被改坏的文件，点击 AI 修改前的历史快照一键还原。
   - **JetBrains 全家桶（PyCharm / IntelliJ / WebStorm）**：右键文件或目录 → **Local History → Show History**，直接对比并回滚到任意时间点。
2. **操作系统回收站 / 云盘历史版本**：检查系统回收站、OneDrive / iCloud / Dropbox 历史版本。
3. **极端无 IDE 历史时的日志取证与重建**：若以上均不可用，再参考 [第 5 课 · 极端场景灾难恢复顺序](05-高阶审计与事故博物馆.md) 从 Agent 会话日志中打捞原文，或按原意重建（并显式标注“非原件重建 + 缺失部分清单”）。
