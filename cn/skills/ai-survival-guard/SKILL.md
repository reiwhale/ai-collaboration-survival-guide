# AI 协同防翻车护栏（自包含轻量技能）

在当前工作区落地以下四条极简安全护栏，不增加冗余流程，不拖慢日常改动：

1. **分清提问与动手，高风险改动先确认**
   - 提问（“是不是 / 为什么 / 要不要”）或方案探讨保持严格只读，零改盘。
   - **Git 能一键还原且范围清晰的常规小改直接执行**；遇到**不可逆操作**（删除未跟踪文件、清库、改外部服务、强推远端）、**未初始化 Git 的大改动**或**架构大改 / 需求有歧义**时，先给出方案与影响范围，等用户确认再动。
   - 需要澄清歧义或请用户拍板时，优先调用宿主自带的选择题提问工具；在纯终端或无该工具时，提供 2–4 个带「推荐项 + 一句话白话解释」的 `A/B/C` 选项。

2. **让错误不疼：Git 检查点 + 2 次无新进展熔断**
   - 大改前先确认存在干净的 Git 提交（未初始化时先提醒 `git init`）。
   - 清理废弃文件优先移入 `_trash_box/`（确认已写入 `.gitignore` 防止误提交），待运行稳定后再由用户确认清空；禁用通配符群删（`rm -rf *`、`*.py`）与 `git reset --hard`。
   - **同一报错连续 2 次尝试均无新信息/新进展时，立即停手**，提示用 `git stash` / `git revert` 退回干净基线再换思路。

3. **只报实测事实，不知直说**
   - 文件路径、符号名、报错信息必须从源码或命令输出逐字核实，不许猜测 API；宣称“未找到”前先确认扫描范围。
   - **只要修改了代码或配置**，收尾只给三句干货：**改了哪些文件 · 实跑了什么命令及真实结果 · 还有哪些范围未覆盖**（Mock 测试不替代真实环境验收）。

4. **源码优先，新坑入冷，按需探环境**
   - 长期未更新的文档仅作参考，一切以当前现行源码为准（`Code > Docs`）。
   - 项目专属踩坑记入冷层 `docs/lessons.md`，不要往常驻规则里硬塞长条文。
   - 若当前项目配有可选的 `scripts/probe_env.py`，遇到环境/编码报错或收到 `/sync-env` 时只读重跑刷新本地 `.agent-env.local.txt`。
