# AGENTS.md · 轻量人机协同规则（Lite）

> 定位：只给 AI 加四道“防删库 / 防死磕 / 防瞎编”的刹车线，绝不拖慢日常写代码节奏。

1. **分清提问与动手，高风险改动先确认**  
   用户发问（“是不是/为什么/要不要”）或探讨时，只答不动盘。**Git 能一键还原且范围清晰的常规小改直接做**；遇到**不可逆操作（删除未跟踪文件、清库、改外部服务、强推远端）**、**尚未初始化 Git 的大改动**或**架构大改 / 需求有歧义**时，先给方案与影响范围，等点头再动。需用户拍板或澄清歧义时，优先调用宿主自带的选择题提问工具；纯终端或无该工具时，给 2–4 个带「推荐项 + 一句话白话解释」的 `A/B/C` 选项，方便点选、单字回复或自由补充。
2. **让错误不疼：保底存档 + 2 次无新进展熔断**  
   大改前确认存在可用 Git 提交（未初始化时先提醒 `git init`）。清理废弃文件优先移入 `_trash_box/`（先确认已写入 `.gitignore` 防误提交），待跑稳后由用户确认清空；禁用通配符群删（如 `rm -rf *`、`*.py`）与 `git reset --hard`。**同一个报错连续 2 次尝试均无新信息/新进展时，立刻停手**，提示 `git stash` / `git revert` 退回干净基线再换思路。
3. **只报实测，不知直说**  
   不许猜文件路径或 API 签名，找不到直说未知或标 `[待查]`；搜不到东西先核对扫描范围。**有代码/配置改动时**，收尾只写三句干货：**改了哪几个文件 · 跑了什么验证命令与结果 · 还有哪没验（AI 自写 Mock 测试不替代真实环境）**。
4. **源码优先，新坑入冷，按需探环境**  
   长久未动的文档一律当参考，以当前源码为准（`Code > Docs`）。项目专属踩坑记入冷层 `docs/lessons.md`，不要往本文件硬塞条文。若项目配有 `scripts/probe_env.py`，遇环境报错或收到 `/sync-env` 时运行它刷新本地画像。
